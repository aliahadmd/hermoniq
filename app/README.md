# Harmoniq Mobile App

Expo React Native app for Harmoniq. This app provides the mobile experience for authentication, money tracking, habit tracking, notes, planner events, profile/settings, and AI chat.

Run commands from this directory. The Cloudflare backend is a separate project in `../backend`.

## Stack

- Expo SDK 54 and React Native 0.81.
- Expo Router v6 with typed routes.
- React 19 and React Compiler.
- TanStack React Query for server state.
- Zustand for persisted local app state.
- Better Auth Expo client.
- React Hook Form and Zod validators.
- NativeWind/Tailwind classes for styling.
- Expo Notifications for habit, money, and planner reminders.

## Project Structure

## Local Development

Start the backend first:

```bash
cd ../backend
npm run dev
```

Then start Expo:

```bash
cd ../app
npm start
```

The app reads `EXPO_PUBLIC_API_URL` in development:

```bash
EXPO_PUBLIC_API_URL=http://localhost:5173
```

Production builds ignore the local override and use the deployed backend URL from `lib/base-url.ts`.

For Android emulators, `localhost` may refer to the emulator itself. Use a host address reachable from the emulator when needed, for example the LAN IP printed by Expo/Metro.

## App Entry and Routing

The app entry is Expo Router:

```text
main: expo-router/entry
```

The route tree lives under `app/`. Important route groups:

- `(auth)`: unauthenticated screens.
- `(tabs)`: main tab navigator.
- `assistant/[id]`: AI chat thread.
- `money-tracker/*`: money workflows.
- `habits/*`: habit workflows.
- `planner/*`: event workflows.

If Expo shows the default starter text, check that this directory contains the real `app/` route tree and that it was not replaced by an empty starter folder.

## Backend Connection

API and auth clients resolve the backend through `lib/base-url.ts`.

Development:

```text
EXPO_PUBLIC_API_URL=http://localhost:5173
```

Production fallback:

```text
https://harmoniq-backend.aliahad.workers.dev
```

The backend API is authenticated with Better Auth session handling.

## Feature Areas

- Money: accounts, categories, transactions, budgets, and dashboard charts.
- Habits: creation, logging, preferences, reminders, and progress screens.
- Notes: categories, pinned notes, archived notes, drafts, and templates.
- Planner: events, reminders, and editing flows.
- AI assistant: chat threads, context chips, pending actions, image attachments, and settings.
- Profile/settings: user profile and per-feature settings.

## Troubleshooting

After moving this project folder, clear stale Metro/Watchman state:

```bash
npm install
npx expo start --clear
watchman watch-del "$(pwd)" || true
watchman watch-project "$(pwd)" || true
```

If Metro cannot resolve `@/...` imports:

- Confirm `app/tsconfig.json` still maps `@/*` to the project root.
- Confirm the route directory is `app/app/` from this project root.
- Restart Expo with a cleared cache.

If Android cannot reach the backend:

- Confirm `../backend` is running.
- Set `EXPO_PUBLIC_API_URL` to an address reachable from the emulator/device.
- Rebuild/restart the development app after changing environment variables.

## Notes

- Keep `lib/validators.ts` in sync with `../backend/src/worker/validators.ts`.
- No mobile test framework is currently configured.
- Do not commit local secrets, keystores, or machine-specific build artifacts.
