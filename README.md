# Harmoniq

Harmoniq is a personal finance and lifestyle product with two independent TypeScript projects:

- `app/`: Expo React Native mobile app for Android, iOS, and web development builds.
- `backend/`: Cloudflare Workers API, admin dashboard, database schema, AI assistant, and tests.

There is no monorepo tooling at the root. Install dependencies and run commands from the project directory you are working in.

## Product Areas

- Authentication with Better Auth.
- Money tracker: accounts, categories, transactions, dashboards, and monthly budgets.
- Habit tracker: habit setup, preferences, logs, reminders, and progress views.
- Notes: categories, pinned notes, archived notes, drafts, and templates.
- Planner: events, reminders, and ICS import support.
- AI assistant: chat sessions, image attachments, Vectorize memory, Workers AI model calls, structured pending actions, and optional AutoRAG search.
- Admin dashboard: React/Vite app served with the Worker for user administration.

## Quick Start

Install each project separately:

```bash
cd backend
npm install

cd ../app
npm install
```

Run the backend from the repository root:

```bash
cd backend
npm run dev
```

Run the mobile app from the repository root:

```bash
cd app
npm start
```

For local mobile development, set the app API URL to the backend dev server:

```bash
EXPO_PUBLIC_API_URL=http://localhost:5173
```

On Android emulators, use the host-machine address that the device can reach if `localhost` does not work.

## Environment

Backend configuration lives in `backend/wrangler.json` and Cloudflare secrets. Important bindings include:

- D1 database: `DB`
- Workers AI: `AI`
- Durable Object: `AI_CHAT_SESSION`
- Vectorize: `CHAT_MEMORY_INDEX`
- R2 bucket: `AI_CHAT_MEDIA_BUCKET`
- Email secrets: `RESEND_API_KEY`, `EMAIL_FROM`

Mobile configuration uses `EXPO_PUBLIC_API_URL` for local development. Production builds fall back to the deployed Cloudflare Worker URL defined in `app/lib/base-url.ts`.

Do not commit production secrets. Use Wrangler secrets for deployed values.

## AI Assistant

The backend AI assistant is implemented in the Worker under `backend/src/worker/ai/` and `backend/src/worker/agents/`.

Current model configuration:

- Chat/action model: `@cf/google/gemma-4-26b-a4b-it`
- Vision model: `@cf/llava-hf/llava-1.5-7b-hf`
- Embedding model: `@cf/baai/bge-base-en-v1.5`

The assistant builds a user-scoped ecosystem context from money, habits, notes, events, and profile data. It may propose one pending action at a time, but data-changing actions are only executed after explicit user confirmation.

## Development Notes

- Keep backend and app validators in sync when changing shared request shapes.
- Every backend query on user-owned data must include `userId` ownership scoping.
- The mobile app uses Expo Router route groups: `(auth)` for auth screens and `(tabs)` for main tabs.
- The backend test suite uses an in-memory SQLite database and Hono request helpers.
- After moving this folder, reinstall dependencies if paths are stale and clear Metro/Watchman cache if the app cannot resolve files.

Useful reset commands after moving the project:

```bash
cd app
npm install
npx expo start --clear
watchman watch-del "$(pwd)" || true
watchman watch-project "$(pwd)" || true
```
